# vmtest

Runs real-disk scenarios inside an Arch ISO VM (QEMU, KVM, OVMF/UEFI). All root work happens in the guest, never on the host.
Needs QEMU, bsdtar, edk2-ovmf and an `archlinux-*.iso` in `~/ISOs` (the newest is used). Guest packages come from the Arch Linux Archive snapshot of the ISO's build date, and only one `run.py` runs at a time (a lock in `.cache/`).
Run: `python scripts/vmtest/run.py [--keep] [--timeout SECS] SCENARIO...|all|gui` (`all` is every non-GUI scenario). Exit 0 only if every scenario prints `PASS`.
A scenario is `scenarios/<name>.py` with `DISKS`, `BOOT` and `run(ctx)`; raise `AssertionError` to fail. Disk builders live in `fixtures.py`.
`BOOT = True` scenarios run the full install from the newest `~/XeroBuild/XeroISO/xerolinux-*.iso` (second CD-ROM, `boot_config.yaml`), then reboot QEMU from the target disk alone with the same OVMF VARS and pass when `xenboot login:` reaches the serial console (`--install-timeout`, `--login-timeout`). An optional `verify(ctx, state)` then runs in the Arch ISO again with what `run` returned. With `BOOT_PASSPHRASE` set, the boot phase uses a socket serial port, types the passphrase at each `Enter passphrase for` prompt, and requires exactly one prompt (GRUB's: the initramfs must unlock root with its embedded keyfile).
Boot files and per-run disks are cached in `scripts/vmtest/.cache/` (gitignored); `--keep` leaves the run's disks and `serial-<phase>.log` files there.
`GUI = True` scenarios (`gui_*`) drive the real installer: `makepkg` builds xen-app and xen-cfg-xerolinux from the working tree, the newest XeroLinux ISO boots to its live Plasma desktop, and a root command agent (`guest_agent.py`, installed by a `systemd.extra-unit` SMBIOS credential, talking over virtio-serial) `pacman -U`s the packages, adds `console=ttyS0` to the bootloader job of the in-RAM `/etc/xen/xerolinux.yaml` and starts the menu entry (`kioclient exec xen.desktop`, so xen-polkit, pkexec and xen-root-launch). `gui.py` then clicks and types through QMP (usb-tablet, 1920x1080) and checks every step with tesseract OCR on a screendump; each page is saved to `.cache/gui-<scenario>/NN-<page>.png`. An optional `prepare(ctx)` runs in the Arch ISO first (its return value reaches `verify`), `drive(g)` handles the Partition page, and after Reboot Now the target disk boots alone as for `BOOT` scenarios. Needs `tesseract` with the `eng` model (`tesseract-data-eng`, or `eng.traineddata` in `.cache/tessdata`) and python-pillow.
